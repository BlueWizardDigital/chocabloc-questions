# What `normalizeQuestion` rewrites

**Branch on the normalised question, never on the bank row.** `normalizeQuestion` is not a
validator that passes rows through — it rewrites `format`, overrides `imageType`, and rebuilds
`content`. A guard, theme rule, or renderer switch written against the fields the API sent will
silently stop matching as soon as the row goes through the normalizer, and a silent mismatch
ships as broken UI rather than an error.

This has bitten Adventure 101 twice: a guard keyed on the bank's `imageType`, which the
normalizer had already replaced, and a coin renderer keyed on `content.coins`, which the
normalizer had already moved to `content.coinScene`.

Source of truth is `src/helpers/normalizer.ts`. The tables below were generated by running rows
through it, not by reading it.

---

## The two paths do different things

Which path a row takes depends on one thing: whether it has a `choices` array.

| Row shape | Path | What happens |
|---|---|---|
| has `answer` (+ `distractors`) | per-format normalizer | everything in the tables below |
| has `choices` (F6, `F6_DROP_ANSWER=true`) | choices-only short-circuit | `format`, `imageType` and `content` **pass through untouched** |

The choices-only path (`doNormalize`, the `Array.isArray(r['choices'])` branch) skips the
per-format normalizers entirely — they require `answer` and would throw. It keeps the bank's
`format`, its raw `imageType` string (unvalidated), and its `content` object as-is. It sets
`choices`, and omits `answer` and `distractors`.

Its only rewrite is text routing, which mirrors the per-format normalizers:

| Condition | Becomes |
|---|---|
| format is one of the 70 stem formats | `text`, `content: { stem }` |
| `multiplication` with no `array`/`number_line` imageType | `text` |
| `pattern` with no `content.sequence` array | `text` |

**The two paths can disagree**, and that asymmetry is what to check first when a question renders
correctly in one environment and not another. Before v0.6.0-beta.13, `geometry_properties`
reached the renderer as `shape_2d` on the choices-only path and `shape_3d` on the answer-bearing
path, from the same bank row.

## `format` rewrites

| In | Out | Why |
|---|---|---|
| any of the 70 stem formats (`addition`, `subtraction`, `algebra_solve`, `ratio`, `money_round`, …) | `text` | the stem carries the whole question |
| `money_coin_colour` · `money_coin_denomination` · `money_coin_name` · `money_coin_size` | `text` **+ `content.coinScene`** | stem formats that also get a synthesised coin scene; the coin pile renders them, not the text fallback |
| `money_count_mixed` | `money` | alias — same normalizer |
| `base10_count` · `base10_block_count` · `base10_regroup` · `base10_compare` | `base10_blocks` | aliases — the operation moves to `content.operation` |
| `pattern` with no `content.sequence` array | `text` (if `questionText` is set; **throws** otherwise) | the sequence is only in the stem |
| `multiplication` with no `array`/`number_line` imageType | `text` | nothing to draw |

Everything else keeps its format.

---

## `imageType` overrides

Most formats **ignore** whatever the bank sent and set `imageType` themselves. Feeding
`shape_2d` to `geometry_volume` gets `shape_3d` back.

| Formats | `imageType` becomes |
|---|---|
| `geometry_attributes` · `geometry_symmetry` · `geometry_classify_triangle` · `geometry_circle_convert` | `shape_2d`, always |
| `geometry_face_identify` · `geometry_volume` · `geometry_surface_area` | `shape_3d`, always |
| `money` (and `money_count_mixed`) | `coins` |
| `pythagorean` | `right_triangle` |
| `geometry_angle_classify` | `angle` |
| `geometry_circle_parts` | `circle_parts` |
| `fraction_concept` | `fraction_visual` |
| `time` | `analog_clock` |
| `pattern` | `pattern_visual` |
| `coordinate_distance` | `coordinate_plane` |
| `money_budget_adjust` | `table` |
| `base10_blocks` (and its aliases) | `base10_blocks` |
| `geometry_area` · `geometry_angles` · `geometry_perimeter` · `geometry_circumference` | `undefined` — dropped |
| `text` and every stem format | `undefined` |

Only five formats read the bank's `image_type` / `imageType` at all:

| Format | Accepted | Missing or unrecognised |
|---|---|---|
| `geometry_classify` | `shape_2d` · `shape_3d` | `shape_3d` |
| `geometry_properties` | `shape_2d` · `shape_3d` | `shape_3d` (since v0.6.0-beta.13; before that it was forced to `shape_3d` outright) |
| `geometry_identify` | `shape_2d` · `shape_3d` | `shape_2d` |
| `data_graph` | `bar_graph` · `pictograph` | **throws** |
| `multiplication` | `array` · `number_line` | routes to `text` |

`geometry_area` is the one conditional case: `compound_shape` when `content.components` holds two
or more entries, `undefined` otherwise.

## `content` rebuilds

`content` is rebuilt from scratch for every format. Keys the format does not name are **dropped** —
including `content.operation`, which only `base10_blocks` keeps.

| Format | What changes |
|---|---|
| every stem format | `content` becomes `{ stem }`. `operands`, `result` and everything else are gone. `stem` is `questionText` if present, otherwise built from the format and operands |
| `money_coin_*` | `content` becomes `{ stem, coinScene }`. `coins: ['loonie', 'dime']` (a list of names) becomes `coinScene.coins: { loonie: 1, dime: 1 }` (a count map) with a `currency`. Names not valid for the currency are dropped; if no coins survive, or the currency cannot be determined, `coinScene` is **omitted** and the question renders as bare text |
| `money`, `money_count_mixed` | `content` becomes `{ currency, coins }`. `currency` is inferred from a `-USD` / `-CAD` suffix on the skill ids (both present → throws). Coin keys not valid for that currency, and non-numeric values, are dropped. A numeric-string `answer` is coerced to a number (cents) |
| `geometry_circumference` | `content.diameter` becomes `content.radius` (halved). `diameter` does not survive |
| `data_graph` | `content.question` is added, `''` when the row has none |
| `base10_blocks` + aliases | `content.blocks` is filtered to `thousands` / `hundreds` / `tens` / `ones` numeric keys; anything else is dropped. `blocks` is always present, `{}` when there was nothing usable |
| `base10_compare` | `content.set_a` / `set_b` are rebuilt as `{ number, blocks }`, `number` defaulting to `0` |
| `geometry_area` | `content.components` keeps only entries with numeric `width` **and** `height` |
| `pattern` | `content.sequence` entries are coerced to strings |
| `fraction_concept` | `content.fraction` must be `[numerator, denominator]` numbers, else throws |

## Field renames

Applied to every row, on both paths.

| Bank row | Normalised |
|---|---|
| `question_id` or `id` | `id` |
| `skill_ids` or `skillIds` | `skillIds` |
| `image_type` or `imageType` | `imageType` |
| `answer_token` or `answerToken` | `answerToken` |
| `answer_mode` / `answer_type` | `answerMode` (`'choice'` \| `'input'`) |
| `answer_display` | `answerDisplay` |
| `distractors[].error_type` | `distractors[].errorType` (`'unknown'` when absent) |
| `distractors[].value_display` | `distractors[].label` |

`questionText` is read from `questionText` only — not from `prompt`, `content.question` or
`content.prompt`.

---

## When a row cannot be normalised

- **Production** (`isProd()`): `normalizeQuestion` returns `null` and calls `opts.onMalformed`.
  `normalizeBatch` skips the row. A short pool is the symptom, not an exception.
- **Development**: it throws `NormalizeError`.
- A row carrying the legacy `correctIndex` field throws in both, always.

---

## If you are writing a guard

1. Normalise first, then inspect. `normalizeQuestion(row)` and branch on the result.
2. Do not read `imageType` off the bank row. For all but five formats it is discarded.
3. Do not read `content.operation`, `content.operands` or `content.coins` off the normalised
   question — they are not there. Read them off the **raw** row, which is what the word-problem
   engine does (`applyWordProblem` runs pre-normalize for exactly this reason).
4. Never mutate `question.id`. The F6 `answerToken` is an HMAC bound to it.
5. If a guard has to distinguish the two paths, test for `choices` — its presence is what selects
   the choices-only short-circuit.
